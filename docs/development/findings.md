# 调研发现

- KiCad 当前源码 `PATHS::CalculateUserSettingsPath()` 先取平台用户配置根目录，再追加 `kicad` 和 `GetMajorMinorVersion()`；设置目录因此分别为 `.../kicad/6.0`、`7.0`、`8.0`、`9.0`、`10.0`，开发版为 `10.99`。
- `KICAD_CONFIG_HOME` 是配置根目录覆盖值，KiCad 仍会在其后追加主次版本目录；现有代码把它直接当版本目录使用，存在识别错误。
- `kicad_common.json` 的语言字段在当前源码中为 `system.language`；需要优先读取当前 KiCad 对应版本目录，不能直接选择机器上最新目录。
- KiCad 10.99 的 IPC 插件使用 `plugin.json`、`KICAD_API_SOCKET`/`KICAD_API_TOKEN` 和官方 `kicad-python`。稳定版 0.7.1 已提供 Track、ArcTrack、Via、Group、事务、选择、铜层和网络接口。
- 新 IPC action 作为独立 Python 进程运行，适合使用标准库 `tkinter/ttk`；旧 KiCad 6-10 SWIG ActionPlugin 保留现有 wx 界面以维持兼容。
- IPC 坐标和尺寸使用纳米整数；现有 geometry 模块可继续以毫米计算，在 backend 边界转换为 nm。

## 2026-07-22 电机扇形线圈与架构重构前置调研

- 参考图不是现有“局部中心缩放的渐宽线圈”，而是把每个线圈限制在由 PCB 外圆、中心避让圆、相邻槽边界组成的环形扇区中；多个内缩轮廓以近似恒定节距铺满扇区，槽间保留均匀机械/铜箔间隙。
- 当前 `motor_trapezoid` 使用归一化圆角梯形轮廓，`resolve_motor_spiral_parameters` 仍以单线圈圈数/目标长度为核心，再缩放到整个阵列直径；不能直接表达“固定 PCB 外径和内孔后，按槽数铺满环形区域”。
- 当前转矩推荐只在目标转矩大于零时反推出外径/内径；电压没有进入求解。轴向磁通电机的反电势还依赖转速、每相匝数和磁密，因此只给电压与转矩不足以唯一确定绕组，需要新增目标转速和驱动/相连接假设。
- 当前只有铜箔直流电阻/压降/损耗估算，没有电感模型。Mohan 等人的平面螺旋近似可作为圆形/规则多边形线圈的快速初算，但扇形电机线圈应明确标记为工程近似，并保留后续场求解器校核边界。
- IPC-2152把载流能力定义为电流、导体尺寸和允许温升之间的关系；因此“最佳电流”不能只由铜厚和线宽静态给出，至少需要允许温升/环境条件作为约束或把结果标记为保守估算。
- `SettingsStore.load()` 已能在文件缺失、损坏或类型错误时回退 `DEFAULTS`；问题主要是 legacy 路径硬编码 `kicad_spiral_plugin/settings.json`，IPC 则使用插件设置目录中的通用 `settings.json`，尚无与 CoilForge 名称一致的统一命名；最终决定不迁移旧路径。
- 当前自动优化会在非 Custom 场景保留最后编辑字段并继续改写其它字段；新需求需要显式“步骤锁定快照 + fixed_keys”，后续求解器只能调整未锁定字段，冲突时返回说明和返回步骤建议。
- 根目录模块互相存在包内/脚本双导入；直接移动会同时影响 KiCad 6–10 SWIG、10.99 IPC、测试和 ZIP 清单。安全方案是保留根目录入口及一版兼容包装器，把实现迁入 `coilforge/` 子包，再让打包器递归收集。
